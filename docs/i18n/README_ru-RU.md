# SDK плагинов MarkText Plus

Основное приложение: [MarkText Plus](https://github.com/SugarFatFree/marktext-plus)

Как написать плагин для MarkText Plus и что редактор ему позволяет, а что нет.

**Предварительный выпуск.** Этот SDK остаётся в 0.x, пока система плагинов не устоится, и описанные здесь манифест и протокол ещё могут меняться между версиями. Что это значит сейчас и что будет значить потом — в разделе [Совместимость](#совместимость) ниже.

## Сначала выберите среду выполнения

Плагин работает на машинах, где есть только редактор — ни Dart SDK, ни Node, ни Python. Этот единственный факт определяет почти всё дальнейшее.

| `runtime` | Что вы поставляете | Где работает | Когда брать |
|---|---|---|---|
| `lua` | один файл `.lua` | на всех платформах, без сборки | обычный случай: команды меню, вопросы, работа с текстом |
| `js` | один файл `.js` | на всех платформах, без сборки | то же самое, если вам привычнее JavaScript |
| `process` | **по исполняемому файлу на платформу** | только там, где вы собрали | нужна настоящая цепочка сборки, библиотеки или долгая работа |
| `data` | вообще без кода | везде | темы, сниппеты, словари |

Начинайте с `lua` или `js`. Такой плагин — это **один файл скрипта и один `manifest.json`, и больше ничего**: ни сборки, ни компилятора, ни второго языка, и эти два файла работают как есть в Windows, macOS и Linux. Уронить редактор скрипт тоже не может.

Берите `process` только тогда, когда скрипта действительно не хватает.

Плагин ИИ-перевода, опубликованный рядом с этим SDK, — это всё, чем плагин на Lua является на диске:

```
manifest.json
plugin.lua
README.md
CHANGELOG.md
LICENSE
```

Скрипт, манифест и три файла документации. **Ни следа Dart.**

## Что лежит в этом репозитории

По каталогу на язык, и каждый — законченный плагин, который можно скопировать:

```
packages/lua/       ← start here
  manifest.json
  plugin.lua              the entrypoint
  lib/marktext-plus.lua   the API, loaded with require("lib.marktext-plus")

packages/js/        ← or here
  manifest.json
  plugin.js
  lib/marktext-plus.js    the API, loaded with require("lib/marktext-plus")

packages/dart/      ← only if a script will not do; any compiled language works
  manifest.json
  plugin.dart             the entrypoint, compiled to an executable
  lib/                    the library it imports
  pubspec.yaml

schema/manifest.schema.json
```

Названы по **языку**, потому что выбираете вы именно его. `runtime` в манифесте говорит, как плагин работает — `lua`, `js`, `process`, — и `packages/dart` это плагин `process`: Dart здесь всего лишь язык, на котором написан его пример.

**Плагин `process` можно написать на чём угодно, что компилируется в исполняемый файл.** Редактор запускает программу и говорит с ней по JSON-RPC через stdin и stdout; он никогда не узнаёт, чем эта программа была создана. Go, Rust, C++, C#, статически слинкованный Python — годится всё, и ничему из этого не нужно из репозитория ничего, кроме протокола:

- по одному объекту JSON в строке, в stdin и stdout;
- ответы возвращают числовой `id`;
- завершаться, когда stdin достиг конца;
- завершаться, если в окружении нет `MARKTEXT_PLUS_PLUGIN_TOKEN`, чтобы запущенный двойным щелчком файл сказал, что он такое, а не ждал.

Это весь договор. Вот он на Python, без единой строчки из этого репозитория — он отвечает редактору и отказывается работать, если его никто не запускал:

```python
#!/usr/bin/env python3
import json, os, sys

if not os.environ.get("MARKTEXT_PLUS_PLUGIN_TOKEN"):
    print("This is a MarkText Plus plugin.", file=sys.stderr)
    sys.exit(1)

for line in sys.stdin:                       # ends at EOF: the editor went away
    line = line.strip()
    if not line:
        continue
    request = json.loads(line)
    if request.get("method") == "shutdown":
        break
    result = {"echoed": request.get("params", {}).get("text", "")}
    print(json.dumps({"jsonrpc": "2.0", "id": request["id"], "result": result}),
          flush=True)
```

[`packages/dart/lib`](../../packages/dart/lib) — те же четыре правила с обработанными краями: неразбираемый ввод, неизвестный метод, ошибка в одном обработчике, которая не завершает весь плагин. Dart здесь потому, что на нём написан сам редактор, и `dart compile exe` был кратчайшим путём к работающему примеру. Это ни требование, ни рекомендация: переписать четыре правила на языке, который вы и так знаете, обычно проще, чем добавлять в свою сборку цепочку инструментов Dart.

Все три точки входа делают одно и то же: загружают API и вызывают его.

```lua
local sdk = require("lib.marktext-plus")
return sdk.ask(sdk.t("ask.language"), { default = ..., choices = ... })
```

```js
const sdk = require("lib/marktext-plus");
return sdk.ask(sdk.t("ask.language"), { default: ..., choices: [...] });
```

```dart
import 'package:marktext_plus_plugin_sdk/marktext_plus_plugin_sdk.dart';
exit(await serve(args, { 'summarise': (request) => ... }));
```

`lua` и `js` — намеренно **один и тот же плагин, написанный дважды**: тот же манифест, те же разрешения, то же поведение, — чтобы их можно было читать рядом. **Копируйте один.** Плагин объявляет один `runtime` и одну точку входа; каталог, где лежат все три, — это три плагина под одним манифестом.

### Почему модуль API лежит внутри примера

Потому что он поставляется вместе с вашим плагином. `lib/marktext-plus.lua` — не зависимость, на которую указывают, а файл, который вы копируете вместе с остальным и который дальше ваш. Скопировав `packages/lua` целиком, вы получаете работающий плагин вместе с API; нет ни второго места, откуда его брать, ни номера версии, за которым нужно поспевать.

### Что такое модуль API

Для скрипта это обычный Lua или JavaScript, **поставляемый вместе с вашим плагином**. Редактор внедряет `storage`, `t` и `require` как глобальные до того, как ваш файл будет прочитан; модуль собирает их под одним именем и добавляет по конструктору на действие, так что плагин читается как `sdk.show(text, title)`, а не как таблица, орфографию которой никто не проверяет. Его можно править, а можно и вовсе не пользоваться — вернуть голую таблицу работает ровно так же.

Для `packages/dart` это настоящая библиотека, вкомпилированная в ваш исполняемый файл, и она несёт то, что скрипту не нужно: цикл JSON-RPC, проверку запуска и завершение. Плагин-процесс находится по ту сторону канала.

## Плагин может состоять из нескольких файлов

`require` загружает один из **ваших собственных** файлов — модуль API выше загружается ровно так же, и всё остальное, что вы положите рядом, тоже:

```lua
local helpers = require("lib.helpers")   -- lib/helpers.lua, returns its table
```

```js
const helpers = require("lib/helpers");  // lib/helpers.js, sets module.exports
```

Загружается один раз, сколько бы раз его ни потребовали. Имя — это имя, а не путь: оно разрешается внутри каталога вашего плагина и больше нигде. Поэтому разбить большой плагин на части — или поставить вместе с ним чью-то библиотеку — не даёт вам ни капли доступа к остальному диску. Имя с разделителем, с `..` или с точкой в начале отвергается до того, как что-либо будет прочитано, а разрешённый файл затем ещё раз проверяется на то, что он внутри вашего каталога — это и ловит символическую ссылку, ведущую наружу.

## Попробовать плагин до того, как его отдать

Плагин на Lua или JavaScript интерпретирует редактор, поэтому честная проверка — установить его: **Плагины → Установить из ZIP**. Скомпилированный можно проверить раньше:

```
cd packages/dart && dart compile exe plugin.dart -o bin/linux/plugin
echo | ./bin/linux/plugin       # should refuse: it was not started by the editor
```

и это вся проверка скомпилированного плагина: он собирается и отказывается работать, когда никто не дал ему токен запуска.

### Установился и не появился

Плагин, чей `manifest.json` не удалось прочитать, в списке не появляется, а отсутствие в списке выглядит ровно так же, как если бы его никогда не устанавливали, — поэтому обычно его устанавливают ещё раз, и снова ничего не появляется.

Редактор перечисляет его отдельно, под загрузившимися, **с причиной**: ключ, который не удалось прочитать, и что там ожидалось. У этой строки есть собственная кнопка удаления — у плагина, который не загружается, нет своей страницы, откуда его можно было бы удалить.

Причина почти всегда одна из этих:

- `runtime` должен быть `lua`, `js`, `process` или `data`
- `lua` и `js` требуют `entrypoint`; `process` требует `entrypoints` — по одному пути на операционную систему
- точкой входа не может быть файл `.dart`. Редактор не поставляется с Dart SDK и не может предполагать, что он есть у читателя, — скомпилируйте и поставляйте исполняемый файл с `runtime: "process"`

## Манифест

`manifest.json` лежит в корне плагина. Редактор читает его, **ничего не выполняя**. См. [`schema/manifest.schema.json`](../../schema/manifest.schema.json).

```json
{
  "id": "com.example.my-plugin",
  "name": "My Plugin",
  "description": "plugin.description",
  "version": "1.0.0",
  "minAppVersion": "1.6.1",
  "runtime": "lua",
  "entrypoint": "plugin.lua",

  "permissions": ["document.read", "ui.contextMenu", "ai.chat", "storage.local"],

  "menus": [
    {"id": "translate.selection", "title": "menu.selection", "location": "editor.contextMenu"}
  ],

  "settings": [
    {"key": "target", "title": "settings.target", "type": "text", "default": "English"}
  ],

  "defaultLocale": "en",
  "locales": {
    "en": {"menu.selection": "Translate selection", "settings.target": "Target language"},
    "zh": {"menu.selection": "翻译选中内容", "settings.target": "目标语言"}
  }
}
```

### Исполняемые файлы по платформам

Плагин `process` не использует `entrypoint`. Он называет свои исполняемые файлы **по операционной системе**, а архитектуру — под ней и только там, где она важна:

```json
{
  "runtime": "process",
  "entrypoints": {
    "macos": "bin/macos/plugin",
    "windows": {
      "x64":   "bin\\windows-x64\\plugin.exe",
      "arm64": "bin\\windows-arm64\\plugin.exe"
    },
    "linux": {
      "default": "bin/linux/plugin",
      "arm64":   "bin/linux-arm64/plugin"
    }
  }
}
```

Система — это часть, на которую отвечать нужно всегда: сборка для Windows и сборка для Linux — разные файлы. Архитектура часто нет, поэтому она необязательна:

- **Один путь на всю систему.** `macos` выше — универсальный бинарник: один файл, содержащий обе архитектуры, как обычно и поставляют сборки для macOS. Писать один и тот же путь дважды, чтобы это сказать, было бы хуже.
- **Таблица архитектур.** `windows` выше поставляет отдельную сборку для каждой и ничего другого не поддерживает.
- **Общий `default` плюс одна специализация.** `linux` выше запускает `bin/linux/plugin` везде, кроме arm64, у которого своя. Побеждает специализированная.

Системы — только `windows`, `macos` и `linux`; архитектуры — только `x64` и `arm64`. **Любое другое имя отвергается при установке, а не пропускается** — иначе написанное с ошибкой `windwos` превратилось бы в момент нажатия в «этот плагин не поддерживает вашу платформу», и объяснить это было бы нечем.

Платформа, для которой вы не собирали, называется по имени, а не угадывается: «нет сборки для `linux-arm64`; есть `macos-x64`, `macos-arm64`, `windows-x64`». Объявить `runtime: "process"` без `entrypoints` или назвать систему и ничего под ней не указать — отвергается и то и другое.

## Как вызывается плагин-скрипт

Обе среды выполнения скриптов синхронны: у интерпретатора Lua нет сопрограмм, а у движка JS нет собственного цикла событий. Всё, что требует времени (спросить читателя, обратиться к модели), заблокировало бы редактор. Поэтому скрипт никогда не ждёт: он **возвращает действие**, описывающее, что нужно сделать; редактор это делает и вызывает скрипт снова, уже с ответом.

```lua
function on_command(ctx)
  -- ctx.command, ctx.selection, ctx.document, ctx.answer
  if ctx.selection == "" then
    return { notify = t("nothing.selected") }
  end
  if ctx.answer == nil then
    return {
      ask = t("which.language"),
      default = storage.get("target") or "English",
      choices = { "English", "简体中文", "日本語" },
    }
  end
  storage.set("target", ctx.answer)
  return { ai = "Translate into " .. ctx.answer .. ":\n\n" .. ctx.selection }
end

function on_result(ctx, result)
  return { show = result, title = ctx.answer }
end
```

Та же форма на JavaScript:

```js
function on_command(ctx) {
  if (!ctx.selection) return { notify: t("nothing.selected") };
  if (ctx.answer == null) {
    return { ask: t("which.language"), default: storage.get("target") || "English" };
  }
  storage.set("target", ctx.answer);
  return { ai: `Translate into ${ctx.answer}:\n\n${ctx.selection}` };
}

function on_result(ctx, result) {
  return { show: result, title: ctx.answer };
}
```

### Панель могут спросить ещё раз

Команду, запущенную из панели, могут выполнить второй раз: читатель просит
изменить ответ, а не описывает всё заново. Редактор говорит об этом теми
полями, которые ваш скрипт уже знает:

- `ctx.selection` — это **ваш же прошлый ответ**, потому что уточнение
  относится к черновику перед глазами, а не к документу.
- `ctx.answer` — то, о чём попросили на этот раз: то же поле, в котором
  приходит ответ на ваш `ask`.

Команде, читающей выделение как «часть, с которой работать», менять ничего не
нужно. Команда, игнорирующая `ctx.selection`, будет каждый раз переписывать
документ заново — а просили не об этом.

Поле появляется только если команда что-то спросила изначально: именно туда
приходит уточнение; команда, которая ничего не спрашивает, выполняется один
раз. То, что заменит `apply`, остаётся тем, что назвал первый ответ: более
короткий второй черновик всё равно заменяет абзац, из которого возник первый,
а не черновик, из которого возник он сам — того в документе нет.

### Действия

| Возврат | Что делает редактор | Затем |
|---|---|---|
| `{ ask = "…", default = "…", choices = {…} }` | спрашивает читателя; `choices` показываются как кнопки-чипы, а введённое вместо них берётся как есть | снова вызывает `on_command`, заполнив `ctx.answer` |
| `{ ai = "…" }` | отправляет вашу подсказку модели, которую настроил читатель | вызывает `on_result(ctx, reply)` |
| `{ show = "…", title = "…" }` | показывает один ответ в маленьком окне, с кнопкой копирования | конец; ничего не записывается |
| `{ panel = "…", title = "…" }` | показывает его на панели рядом с документом | конец; ничего не записывается |
| `{ pane = "…", title = "…", slot = "right"\|"bottom"\|"corner", apply = true, replaces = "…" }` | заполняет одну из областей вокруг документа | конец; ничего не записывается |
| `{ pane = "<html>…", title = "…", as = "web" }` | рисует вашу собственную HTML-страницу в этой области, движком системы. Нужен `ui.webview` | stops |
| `{ notify = "…" }` | говорит читателю одну строку | конец |
| `{ diff = { original = "…", result = "…" } }` | показывает два текста рядом | конец; ничего не записывается |
| `{ replace = "…" }` | заменяет выделение | конец |
| `{ ui = <узел>, title = "…" }` | рисует ваш собственный интерфейс — см. ниже | вызывает `on_event(ctx, id, values)`, когда читатель им воспользуется |
| что угодно ещё | ничего | конец |

### Нарисовать свой интерфейс

`ui` несёт дерево, которое редактор рисует своими же виджетами. Узел — это таблица с единственным ключом:

```lua
return sdk.ui({ column = {
  { text = sdk.t("ask.instruction"), emphasis = true },
  { input = { id = "brief", multiline = true, placeholder = "…" } },
  { chips = { id = "idea", options = prompts.writing_ideas(sdk.t) } },
  { row = {
    { spacer = true },
    { button = { id = "go", label = sdk.t("action.write"), primary = true } },
  }},
}}, sdk.t("menu.write"))
```

| Узел | Поля |
|---|---|
| `text` | сама строка; `emphasis = true` рисует её заголовком |
| `input` | `id` (обязательно), `value`, `placeholder`, `multiline` |
| `chips` | `id` (обязательно), `options` — список строк |
| `button` | `id` (обязательно), `label`, `primary` |
| `row` / `column` | список узлов |
| `select` | `id` (обязательно), `options`, `value` — выпадающий список, когда для фишек их слишком много |
| `checkbox` | `id` (обязательно), `label`, `value`; значение приходит как `"true"` или `"false"` |
| `markdown` | Markdown, нарисованный собственным движком редактора — ответ выглядит как документ, о котором он |
| `image` | `source` (обязательно), `height` — см. ниже |
| `spacer` | пустое место; в строке оно отодвигает следующее к краю |

Нажатие кнопки или выбор фишки вызывает `on_event(ctx, id, values)`, где `id` — идентификатор этого узла, а `values` содержит **все поля ввода дерева** по их id. Помнить форму, нарисованную шагом раньше, не нужно — она есть у редактора.

Это не HTML, и в этом весь смысл: это собственные виджеты редактора. Они ничего не стоят при запуске, следуют теме читателя без того, чтобы плагин знал, какая она, и не могут рисовать за пределами выданного им контейнера.

**Картинки.** `source` — одно из трёх:

- `data:`-URI — раскодируется на месте, ничего не покидает машину;
- путь относительно каталога вашего плагина — абсолютный отклоняется: читать файлы с диска читателя — дело `workspace.read`;
- адрес `http(s)` — **забирает редактор**, а не ваш плагин: значит, он следует системному прокси и попадает в журнал вашего плагина с узлом, статусом, размером и временем. Нужен `network.request`.

Последняя строка — намеренно. Вам можно в сеть; читателю можно узнать, куда. **Разрешение, которое потом никто не может проверить, — это обещание, а не разрешение.**

**Узел с опечаткой отклоняет всё дерево** с ошибкой, которую вы увидите, а не молча ничего не рисует. То же с деревом глубже 12 уровней или больше 500 узлов: половина формы хуже, чем её отсутствие — читатель заполнит то, что видно, и нажмёт кнопку, которой никогда не рисовали.

**Что нужно запрашивать.** Эти четыре отклоняются, если манифест не заявил
право:

| Возвращает | Требует |
|---|---|
| `ai` | `ai.chat` |
| `replace` | `document.write` |
| `notify` | `ui.notifications` |
| `pane`, `panel` | `ui.sidebar` |
| `pane` + `as = "web"` | `ui.webview`, который тянет за собой `ui.sidebar` и `network.request` |

`ask`, `show` и `diff` не требуют ничего. Ответить читателю, который только что
вызвал команду, — это и есть работа плагина; требовать за это право означало бы,
что его заявляет каждый плагин, — а право, которое есть у всех, читателю ничего
не сообщает.

**Своя страница.** `as = "web"` рисует текст области как HTML-страницу, а не как
слова. Это единственный путь к интерфейсу, которого редактор не проектировал, и
путь дорогой: всё остальное, что вы можете вернуть, *описывается* редактору —
именованные узлы или текст — и рисуется его собственными виджетами. Поэтому оно
ничего не стоит при запуске и следует теме читателя, а вам не нужно знать, какая
она.

Движок — системный: WebView2 в Windows, WKWebView в macOS, — а **не браузер,
поставляемый с редактором**. Размер загрузки и память остаются прежними, а
настройки прокси читателя действуют без чьего-либо участия. И **ничего не
создаётся, пока плагин не попросит**: кто ни разу не откроет такой плагин, никогда
не заплатит за движок.

Куда ходит страница, записывается в журнал плагина — это и обещает `ui.webview`.
**Отправляйте HTML, а не адрес**: то, что вы рисуете, — ваше, а страница, которой
нужно что-то от сервера, попросит сама.

**Движок есть не на всякой машине.** Linux без пригодного веб-движка получит
строку с именем вашего плагина — не пустую область, которая выглядела бы как
сломанный плагин. Не делайте веб-страницу единственным способом пользоваться
плагином, если не собираетесь оставить этих читателей в стороне.

**Области.** Редактор и так делит вкладку между исходником и предпросмотром; `pane` — это то же деление, предложенное вам. Не больше четырёх ячеек, и **две половины разделённого вида — две из них**: отсюда всё это и выросло, так что документ в разделённом виде — уже две ячейки, прежде чем вы что-либо заполните.

Форма следует за числом ячеек и на каждом шаге симметрична:

| Ячеек | Расположение |
|---|---|
| одна | документ занимает всю вкладку |
| две | бок о бок, по половине |
| три | одна половина поделена, другая целая |
| четыре | слева вверху, справа вверху, слева внизу, справа внизу |

При трёх ячейках и неразделённом документе **вы выбираете, какая половина делится**: заполнив `right`, вы ставите область рядом с документом — делится верх, а другая область берёт нижний ряд целиком; заполнив только `bottom` и `corner`, вы оставляете документу верхний ряд целиком, а две области делят нижний. Читатель потом может переставить это из заголовка области — какая половина поделена, это взгляд на те же области, а не решение, которое вы принимаете за него снова и снова.

Разделители тянутся мышью, как тот, что между исходником и предпросмотром.

Имена `right`, `bottom`, `corner` — ещё и адрес, по которому вы найдёте область позже, чтобы дописать в неё или заменить её содержимое. Одна область так и остаётся одной областью: заполнив только `corner`, вы получите область рядом с документом, а не угол с двумя пустыми ячейками перед ним. А вот направление задаёт имя — только `bottom` помещает область под документ, любое другое место рядом с ним, — потому что переписанный вариант абзаца, который вы сейчас читаете, читается лучше под ним: та же ширина строки, и взгляд идёт вниз, а не вбок. Читатель может перевернуть это из заголовка области. Имя, которого редактор не знает, отклоняется, а не угадывается: область, возникшая там, где вы её не просили, и без всякой возможности узнать почему, хуже отказа.

**Область принадлежит той вкладке, в которой открыта.** Переход на другую вкладку убирает её с экрана, закрытие вкладки закрывает и её, а возвращение показывает снова.

**Предложить записать это обратно.** `apply` добавляет на область кнопку «Применить», которая пишет её содержимое в документ; `replaces` говорит, что именно она заменит, — пустая строка означает весь документ. То, что вернула модель, стоит прочесть прежде, чем оно окажется в том, что писал читатель: поэтому переписанное сначала показывают и пишут, когда он скажет, — через историю редактора, так что одна отмена возвращает всё назад. Что будет заменено, определяется в момент выполнения вашей команды, а не нажатия кнопки: выделение, сместившееся за это время, не отправит текст куда попало. Нужно `document.write`, и редактор проверяет его у кнопки, а не с ваших слов.

**Скажите, что работаете, прежде чем начать.** Действие с областью читается раньше `ai`, поэтому вернуть их вместе значит «поставь это, а потом иди спрашивай» — и область с пустым текстом и запросом позади неё как раз и есть то, что редактор рисует как «идёт работа». Пока не пришёл первый блок, она говорит об этом там, где будет текст; после — надпись уходит в заголовок, чтобы ход работы никогда не лежал поверх пришедшего. Вернув один лишь `ai`, вы оставите экран без изменений на те секунды, что тратит модель, — и это читается как пункт меню, который ничего не сделал.

Закрыть область — это способ читателя вас остановить. Дописывание в закрытую область отклоняется, а не возвращает её по блоку.

**`show` или `panel`.** Несколько строк — это ответ: маленькое окно тут уместно, а панель ради них — больше мебели, чем содержания. Результат размером с документ читатель прикладывает к тому, что у него на экране, и окно поверх экрана — единственное место, куда его нельзя положить.

Один прогон ограничен восемью вопросами, так что скрипт, отвечающий на каждый вопрос новым вопросом, не сможет удержать читателя.

**Подсказка — ваша.** Редактор держит учётные данные и делает запрос; он не переписывает вашу подсказку, и ваш скрипт никогда не видит ключ API. Модели передаётся ровно та строка, которую вы вернули в `ai`.

### До чего может дотянуться скрипт

Только до этого. Ни `os`, ни `package`, ни `dofile`, ни `loadfile`, ни файловой системы, ни сети — плагин-скрипт приходит из репозитория незнакомого человека и получает то, что объявил, и ничего сверх.

| | |
|---|---|
| `storage.get(key)` / `storage.set(key, value)` | собственные настройки, в собственном каталоге. Только строки. Нужно `storage.local` |
| `t(key)` | собственная строка на языке читателя; неизвестный ключ возвращается собой же |
| `require(name)` | один из ваших файлов, разрешается только внутри каталога вашего плагина |
| `ctx.command` | `id` сработавшего пункта меню или команды |
| `ctx.selection` | выделенный текст, `""` когда ничего не выделено |
| `ctx.document` | весь документ |
| `ctx.answer` | то, что читатель ввёл в прошлый раз, иначе nil/undefined |
| `ctx.view` | как читатель смотрит документ: `source`, `preview` или `split` |

### Чего этот Lua не умеет

Интерпретатор — это Lua, написанный целиком на Dart: именно поэтому плагину-скрипту ничего не нужно устанавливать. И он неполон. Все четыре пункта ниже отказывают **молча**, и время уходит именно на это: шаблон, который ничего не нашёл, выглядит ровно как документ, в котором ничего нет.

| Вместо | Берите | Потому что |
|---|---|---|
| `#someString` | `string.len(s)` | бросает `length error`. `#` на *таблице* работает, так что на ощупь их не различить |
| `s:match("%S")`, `%s` | сравнивать символы: `s:sub(i, i) == " "` | классы не находят ничего, и каждая строка кажется пустой |
| `for l in s:gmatch("(.-)\n")` | `s:find("\n", pos, true)` и `s:sub` | не возвращает вообще ничего |
| `s:gmatch("[^\n]*")` | то же самое | никогда не проходит дальше пустого совпадения |

| `return` без значения внутри вложенной функции | `return nil` | он игнорируется, и строки после него выполняются |

**Последний пункт заслуживает большего, чем строка таблицы.** `if not ok then return end` — это то, как охранное условие пишет каждый программист на Lua, и внутри вложенной функции оно не охраняет ничего: строки, которые должны были быть пропущены, выполняются всё равно. Ваша проверка проходит, пустой случай «обработан», и обработка не происходит.

Внутри `while true do ... end` хуже. У цикла нет выхода, и читатель видит редактор, переставший отвечать.

Исправление — одно слово: пишите `return nil`. Это обычный Lua, и он продолжит работать в тот день, когда интерпретатор починят.

Набор тестов самого редактора закрепляет эти пункты, так что если интерпретатор заменят, эта таблица будет исправлена, а не оставлена вводить в заблуждение. Поведение `return` без значения закреплено тестом, который утверждает, что оно **сломано**: день, когда этот тест упадёт, — день, когда обходной путь можно убрать.

Среда JavaScript — QuickJS, и сопоставимых пробелов, которые стоило бы перечислять, у неё нет.

## Разрешения

Объявлены в манифесте, показаны читателю и **проверяются**. VS Code и IntelliJ показывают список разрешений и затем доверяют расширению; здесь никто ничего не рецензирует, поэтому проверяет редактор. Вернуть `{ ai = ... }` без `ai.chat` не вызовет модель — читателю скажут, что плагин об этом не просил.

| Разрешение | Позволяет плагину |
|---|---|
| `document.read` | читать открытый документ и выделение |
| `document.write` | изменять открытый документ |
| `ui.contextMenu` | добавлять пункты в контекстное меню |
| `ui.menuBar` | добавлять пункты в строку меню |
| `ui.toolbar` | добавить кнопку на панель инструментов † |
| `ui.sidebar` | добавить панель в боковую полосу |
| `ui.statusBar` | добавить элемент в строку состояния † |
| `ui.settings` | иметь свою страницу настроек |
| `ui.commandPalette` | добавлять команды в палитру † |
| `ui.notifications` | что-то сказать читателю |
| `ai.chat` | обращаться к настроенной модели (ключ не передаётся никогда) |
| `storage.local` | держать свой файл настроек в своём каталоге |
| `clipboard.read` / `clipboard.write` | буфер обмена † |
| `workspace.read` / `workspace.write` | файлы в открытой читателем папке † |
| `network.request` | делать собственные HTTP-запросы. **Самое широкое, о чём можно попросить**: всё, что плагин может прочитать, он может куда угодно отправить |
| `ui.webview` | открыть свою веб-страницу внутри редактора. **Тянет за собой `network.request`**, и читателю об этом говорят: страница в веб-виде тянет что угодно |

`†` — разрешение существует и показывается читателю, но **за ним пока ничего
нет**: нет ни панели инструментов, ни строки состояния, ни палитры команд, куда
плагин мог бы что-то добавить, и скрипту недоступны ни буфер обмена, ни рабочая
папка. Объявить его сегодня — не получить ничего. Они остаются в списке, потому
что входят в манифест, и будут выполнены, когда возможность появится.

Просите то, чем пользуетесь. Плагин, который просит `network.request` ради пункта меню, читателю стоит отклонить.

## Точки вклада

```json
"menus":    [{"id": "…", "title": "…", "location": "editor.contextMenu", "when": "selection"}],
"commands": [{"id": "…", "title": "…"}],
"toolbar":  [{"id": "…", "title": "…", "icon": "…"}],
"panels":   [{"id": "…", "title": "…", "icon": "…"}],
"pages":    [{"id": "…", "title": "…"}]
```

`title` может быть ключом перевода. `location` — место, которое определяет редактор: плагин кладёт вещи в названные места, никогда не в пиксельные координаты, и никогда не передаёт редактору собственные виджеты.

`panels` ставит значок в правую боковую полосу; нажатие открывает ящик, который заполняется запуском вашей команды с тем же `id`. Нужно `ui.sidebar` и нужен `icon`, потому что полоса — это ряд значков, и запись, которой нечего нарисовать, была бы пустотой, которая что-то открывает. Если ни один плагин не добавил панель, полосы нет вовсе: полоса значков без значков — это ширина, отнятая у документа ни за чем.

Панель спрашивает в своём же ящике: команда, вернувшая `ask`, помещает вопрос туда — его текст, названные вами `choices` и поле, уже содержащее прошлый ответ, — и ответ приходит в тот же ящик. Раньше спрашивали в плавающей карточке, а ответ приземлялся в ящике: один обмен в двух местах. Закрыть ящик — так читатель отказывается. Команда, запущенная из меню, по-прежнему спрашивает в карточке: своего места у неё нет.

`when` говорит, когда пункт меню стоит предлагать: `selection` — только когда есть выделение, `noSelection` — только когда его нет, а отсутствие означает «всегда». Без этого предлагаются сразу все пункты — «Перевести выделенное» без выделения и «Перевести документ», пока читатель указывает на абзац. Значение, которого редактор не знает, отвергается при установке, а не читается молча как «всегда».

## Настройки

Каждое поле в `settings` становится настоящим элементом управления на странице настроек плагина, а рисует его редактор:

| `type` | Элемент |
|---|---|
| `text` | текстовое поле |
| `password` | текстовое поле, не показывающее содержимое |
| `number` | числовое текстовое поле |
| `boolean` | переключатель; сохраняется строками `"true"` / `"false"` |

Значения лежат в `settings.json` в собственном каталоге плагина, так что ни один плагин не может прочитать или переписать настройки другого. То, что читатель сохранил, доходит до уже работающего скрипта на следующей команде, а не при следующем запуске.

## Переводы

`locales` сопоставляет языку ваши строки, `defaultLocale` говорит, на что откатываться. Читатель с `zh_CN` получит `zh_CN`, если вы его положили, затем `zh`, затем ваш язык по умолчанию. Кладите те языки, какие хотите: это ваша таблица, а не редактора.

## Скомпилированные плагины (`runtime: "process"`)

Исполняемый файл запускается дочерним процессом и говорит по JSON-RPC 2.0, по одному объекту JSON в строке, через stdin/stdout. Ответы возвращают числовой `id`. [`packages/dart/lib`](../../packages/dart/lib) в этом репозитории реализует это для плагинов, написанных на Dart и собранных `dart compile exe`.

### Нельзя поставлять исходник, которому для работы нужна цепочка инструментов

Это касается только скомпилированных плагинов и в особенности Dart, потому что на нём написан редактор: `entrypoint: "bin/plugin.dart"` отвергается при установке. Чтобы его запустить, на машине читателя нужен Dart SDK, которого редактор не ставит и наличие которого не может предполагать, — а в релизной сборке нет и интерпретатора, которому его можно было бы отдать. Скомпилируйте (`dart compile exe`) и поставляйте исполняемый файл.

Ничего из этого не относится к плагину на Lua или JavaScript. Их интерпретирует сам редактор, в чём и весь их смысл: ни Dart, ни цепочки инструментов, ни сборки.

**Почему процесс, а не библиотека, которую грузит редактор.** Плагины на Lua и JS и так работают внутри процесса редактора, в его же потоке — это обычный случай, и он держится потому, что они интерпретируются: плохой скрипт бросает ошибку, которую редактор ловит, так что промах кончается сообщением, а не падением. Чего это не покрывает — скрипт, который никогда не возвращается; он замораживает окно ровно так же, и потому правило выше просит вас ограничивать работу самим.

Нативный код убирает и остальную границу. Поток разделяет адресное пространство, поэтому ошибка сегментации, переполнение стека или `abort()` в любом месте загруженной `.so` уносит редактор вместе с несохранённым документом читателя и без всякой возможности сообщить, что случилось; а выгрузка ненадёжна, так что «отключить плагин» на деле его не остановит. Отдельный процесс возвращает всё это: он может упасть, зависнуть, быть убитым по тайм-ауту, а редактор выживет и скажет, чей это был плагин. (Для Dart, впрочем, и выбирать не из чего: у `dart compile` есть `exe`, `aot-snapshot`, `js`, `wasm` и форматы снимков. Подкоманды, которая делала бы вызываемую из C `.so` или `.dll`, **не существует**.)

- **Используйте `serve()`, и следующие два пункта уже улажены.** Целый скомпилированный плагин:

  ```dart
  import 'dart:io';
  import 'package:marktext_plus_plugin_sdk/marktext_plus_plugin_sdk.dart';

  Future<void> main(List<String> args) async {
    exit(await serve(args, {
      'shout': (request) =>
          (request.params['text'] as String? ?? '').toUpperCase(),
    }, name: 'plugin'));
  }
  ```

  ```
  dart compile exe plugin.dart -o bin/linux/plugin
  ```

- **Не работайте, если вас запустил не редактор.** Редактор порождает токен на каждый запуск и передаёт его в переменной окружения `MARKTEXT_PLUS_PLUGIN_TOKEN`; без него `serve()` печатает строку о том, что это за программа, и завершается с кодом 1. Токен, сделанный для одного запуска, не наберёт тот, кому его не давали, и путешествует он в окружении, а не в argv, который может прочитать всё, что умеет запускать `ps`.

  **Что это делает и чего не делает.** Ни одна программа не может помешать выполнить файл, лежащий на диске у читателя: двойной щелчок по вашему исполняемому файлу всегда запустит процесс. Токен делает неподделываемым ваш ответ на вопрос «меня запустил редактор?», и потому процесс запускается, говорит, что он такое, и завершается, а не сидит на stdin, выглядя как зависшая программа. Плагин, пропустивший эту проверку, — плагин, которого никто не защитил; поэтому проверка стоит в `serve()` из SDK, а не только в этом абзаце. Плагины-скрипты получают это даром: файл `.lua` или `.js` интерпретирует редактор, и двойной щелчок в худшем случае откроет текстовый редактор.

- **Завершайтесь, когда stdin достиг конца.** Так вам говорят остановиться, и так же всё происходит само, если редактор исчез, — `serve()` в этот момент возвращает управление. Редактор к тому же записывает процессы, которые запустил, и при следующем старте убирает те, что ещё живы, — но только те, что запустил он. **Процессы, которые запустили *вы*, убирать вам.**
- Оставьте stdout ответам протокола; диагностика идёт в stderr.
- У запросов есть тайм-аут, и тайм-аут убивает только ваш процесс.
- Считайте всё, что присылает хост, недоверенным, и проверяйте.

## Совместимость

Плагин — это файл на чужой машине, который читает этот редактор. Сломать его — не ошибка сборки, которую здесь кто-то увидит: это плагин, который перестал работать у своих читателей. Поэтому:

**`minAppVersion` соблюдается.** Назовите самый старый редактор, с которым ваш плагин работает, и редактор этого держится: более старый откажется его устанавливать и откажется запускать уже установленный, назвав и требуемую версию, и имеющуюся. Раньше это поле читали и игнорировали, что хуже, чем не иметь его вовсе.

**Что редактор не заберёт без предупреждения.** Каждое имя разрешения, каждое значение `runtime`, каждое действие, которое может вернуть скрипт, каждое поле `ctx`, а также `storage`, `t` и `require` закреплены тестом в исходниках редактора. **Добавлять** в эти списки свободно; **убирать или переименовывать** — значит уронить этот тест, и случайно так уже не выйдет.

**Пока это 0.x**, намеренное ломающее изменение всё ещё возможно, и тогда оно попадёт в журнал изменений вместе с тем, что с ним делать. Когда манифест и протокол пролежат нетронутыми достаточно долго, чтобы заслужить доверие, это станет 1.0 и на том закончится: после этого всё, что плагин может написать сегодня, продолжит работать, а исчезать вещи будут только после того, как их объявят устаревшими в выпуске, который их ещё поддерживает.

**Где плагин сам по себе.** Редактор не может обещать ни поведение вашей подсказки, ни модель, которую настроил читатель, ни дочерние процессы, которые плагин `process` запустил сам. Не может он и помешать читателю запустить ваш исполняемый файл вручную — что он делает вместо этого, сказано выше, про токен запуска.

## Правила безопасности

- Никогда не пишите ключ API в каталог плагина или в манифест.
- В stdout не идёт ничего, кроме сообщений протокола.
- Ограничивайте работу сами. Скрипт выполняется в собственном потоке редактора,
  и ничто его не прерывает: цикл без выхода замораживает окно до тех пор, пока
  кто-нибудь не убьёт процесс. Тайм-аут есть только у скомпилированных плагинов —
  только они являются отдельным процессом, который можно прервать.
- Плагин-ZIP с записью, выходящей за пределы каталога, отклоняется при установке;
  так же отклоняется архив больше 64 МБ, архив более чем с 10000 записями и
  архив, распаковывающийся более чем в 256 МБ. Исполняемый файл для трёх
  платформ помещается; закоммиченный каталог сборки — нет.
